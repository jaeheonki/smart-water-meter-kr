# 일일 검침 수정과 Android 사진 선택 오류 개선 계획

## 목표

- 기기별 한국 시간 기준 하루에 검침 기록을 한 건만 유지한다.
- 당일 기록이 있으면 신규 등록 대신 `오늘 기록 수정`으로 같은 행을 갱신한다.
- 당일 수정은 코인, 연속 기록, 알림 완료를 중복 반영하지 않는다.
- Android에서 갤러리 버튼을 실제 사진 선택에 연결하고 카메라 취소를 서버 오류와 구분한다.
- 홈의 고정 13일 데모 값을 실제 검침 이력 기반 값으로 교체한다.

## 구현 순서

1. 백엔드 일일 기록 계약을 테스트로 고정한다.
   - `GET /meter/today`로 오늘 기록 유무를 조회한다.
   - `POST /meter/manual`은 오늘 기록이 있으면 409를 반환한다.
   - `PUT /meter/today`는 오늘 행을 갱신하고 직전 날짜 기록 기준으로 계산한다.
   - 검증은 `uv run pytest tests/api/test_meter.py`로 수행한다.
2. Android 사진 입력 오류를 테스트로 재현한다.
   - 갤러리 버튼이 `CameraSource.Photos`를 호출하도록 한다.
   - 네이티브 카메라 취소 메시지를 정상 취소로 처리한다.
   - 촬영·파일 변환 오류와 서버 전송 오류 문구를 분리한다.
   - 검증은 Node 계약 테스트와 Vite 빌드로 수행한다.
3. 프론트의 당일 상태와 수정 흐름을 실제 API에 연결한다.
   - 앱 시작 시 오늘 기록과 실제 이력을 조회한다.
   - 오늘 기록이 있으면 홈 버튼을 `오늘 기록 수정`으로 표시한다.
   - 수정 완료 시 보상과 연속 기록을 추가하지 않는다.
   - 검증은 Node 계약 테스트와 Vite 빌드로 수행한다.
4. 전체 회귀 검증과 Android APK 재빌드를 수행한다.
   - 전체 pytest, Node 테스트, Vite 빌드, Capacitor sync, Gradle 빌드를 실행한다.
   - 서버 `/health`와 `/meter/scan`을 실제 요청으로 확인한다.

## 결정 사항

- 하루 경계는 서버 위치와 무관하게 `Asia/Seoul` 기준으로 계산한다.
- 당일 수정은 사진 인식과 직접 입력을 모두 허용한다.
- 당일 수정 시 기존 행의 `recorded_at` 날짜는 유지하고 값, 입력 방식, 신뢰도만 갱신한다.
- 과거 기록 수정은 이번 범위에 포함하지 않는다.
