# 설정 확장과 매일 검침 알림 설계

## 1. 목표

계정 기능 없이 현재 기기를 기준으로 다음 설정 기능을 제공한다.

- 사용자가 지정한 시각의 매일 검침 로컬 알림.
- 당일 검침 완료 시 해당 날짜의 알림 건너뛰기.
- 계량기 교체 이력 조회.
- 체감 가능한 글자 크기 조절.
- 서버와 기기의 모든 데이터를 지우는 앱 초기화.

Android 앱 래핑 전에는 웹에서 설정 UI와 서버 계약을 검증하고, 실제 알림 권한·예약·탭 이동은 Android 실기기 단계에서 검증한다.

## 2. 범위

### 포함

- 알림 켜기·끄기.
- 알림 시각 설정. 기본값은 오후 8시다.
- 알림 제목 `방울이가 마를 것 같아요!`.
- 알림 내용 `오늘의 수도 계량기를 검침해 주세요.`.
- 알림 탭 시 검침 촬영 화면 이동.
- 당일 검침 성공 시 당일 알림 취소 및 다음 날부터 재예약.
- 교체일, 교체 전 마지막 검침값, 새 계량기 기준값, 입력 방식 목록.
- 글자 크기 `0.9배·1.0배·1.15배`.
- 현재 기기의 검침·교체 이력·지역 설정과 로컬 앱 상태·알림·기기 ID 전체 초기화.

### 제외

- 계정, 로그인, 여러 기기 동기화.
- 서버 푸시와 서버 알림 스케줄러.
- Android 정확 알람 권한.
- 이메일, 문자, 주간 리포트 알림.

## 3. 아키텍처와 데이터 소유권

### 3.1 알림

알림 설정은 로컬 앱 상태에 저장한다.

```text
notificationEnabled: boolean
notificationTime: "HH:mm"
```

공식 `@capacitor/local-notifications` 플러그인 하나만 추가한다. 플러그인은 서버 없이 기기 예약, 권한 확인·요청, 예약 취소, 알림 탭 이벤트를 제공한다.

- 웹은 설정값 저장과 화면 상태를 지원한다. 실제 시스템 알림은 예약하지 않는다.
- Android는 알림을 처음 켤 때 권한을 확인하고 필요할 때 요청한다.
- 권한이 거절되면 `notificationEnabled`를 `false`로 유지한다.
- 시간을 변경하면 기존 방울이 검침 알림을 취소하고 새 시간으로 향후 60일을 다시 예약한다.
- 알림을 끄면 방울이 검침 알림 예약만 취소한다.
- 일반 알람을 사용하므로 Android 절전 정책에 따라 선택 시각보다 늦게 표시될 수 있다.
- 알림은 반복 예약 하나가 아니라 로컬 날짜별 고유 ID를 가진 60개의 일회성 예약으로 구성한다. 앱 시작, 알림 설정 변경, 검침 저장 성공 시 예약 창을 다시 향후 60일까지 채운다.
- 앱을 60일 넘게 한 번도 열지 않으면 예약 창이 소진되어 이후 알림은 앱을 다시 열 때까지 멈춘다. 일 1회 검침을 목표로 앱을 정기적으로 여는 현재 제품 범위에서 이 제한을 수용한다.

알림 로직은 화면에서 플러그인을 직접 호출하지 않고 `frontend/src/notifications.js` 어댑터를 통해 사용한다. 어댑터는 권한 확인, 예약 교체, 취소, 탭 이벤트를 한 곳에서 관리한다.

### 3.2 당일 검침과 알림 건너뛰기

검침 저장 성공 시 해당 기기의 로컬 날짜를 완료일로 기록한다.

```text
lastReadingDate: "YYYY-MM-DD"
```

알림이 켜져 있을 때 검침에 성공하면 오늘 날짜의 예약을 취소하고 내일부터 향후 60일을 다시 채운다. 앱 시작과 알림 설정 화면 진입 시에도 예약을 조정해 다음 조건을 보장한다.

- 오늘 검침 전이고 선택 시각 전이면 오늘을 포함해 60일을 예약한다.
- 오늘 검침을 완료했거나 선택 시각이 지났으면 다음 날부터 60일을 예약한다.
- 알림이 꺼져 있으면 예약하지 않는다.

사진 인식만 성공하고 검침값 저장이 실패한 경우에는 완료로 처리하지 않는다. `POST /meter/manual`의 성공 응답을 받은 뒤에만 완료일을 갱신한다.

### 3.3 계량기 교체 이력

서버의 `Reading.is_baseline` 행을 원본으로 사용한다. 새 엔드포인트를 추가한다.

```http
GET /history/replacements
X-Device-ID: <device-id>
```

응답 항목은 다음과 같다.

```json
{
  "replaced_at": "2026-07-16T09:22:50",
  "previous_reading_m3": 1000.0,
  "baseline_reading_m3": 20.0,
  "input_mode": "manual"
}
```

현재 기기의 검침만 대상으로 최신 교체부터 반환한다. 기준점 바로 전 행이 없으면 `previous_reading_m3`는 `null`이다. 설정 화면의 `계량기 교체 이력` 카드에서 별도 목록 화면으로 이동한다.

### 3.4 앱 초기화

현재 기기 서버 데이터를 원자적으로 삭제하는 엔드포인트를 추가한다.

```http
DELETE /device-data
X-Device-ID: <device-id>
```

삭제 대상은 해당 기기의 `Reading` 전체와 `Settings` 한 행이다. 다른 기기 데이터는 삭제하지 않는다.

초기화 순서는 다음과 같다.

1. 삭제 항목을 설명하는 첫 확인을 표시한다.
2. `모든 데이터 삭제` 최종 확인을 받는다.
3. 서버 삭제를 요청한다.
4. 서버가 성공한 경우에만 로컬 알림 예약을 취소한다.
5. 앱 상태와 `device_id`를 삭제한다.
6. 기본 상태를 만들고 온보딩 첫 화면으로 이동한다.

서버 삭제가 실패하면 로컬 데이터, 기기 ID, 알림 예약을 모두 유지하고 카드 안에 오류와 재시도를 표시한다. 네트워크 단절 상태에서는 완전 초기화를 완료하지 않는다.

## 4. 설정 화면 구성

설정 화면의 순서는 다음과 같다.

1. 이름.
2. 글자 크기.
3. 가계부 표시 단위.
4. 지역.
5. 매일 검침 알림.
6. 계량기 교체 이력.
7. 앱 초기화.

### 4.1 매일 검침 알림 카드

- 알림 켜기·끄기 토글.
- 알림이 켜진 경우에만 활성화되는 시간 입력.
- 현재 권한 거절 안내와 재시도 버튼.
- 설명 문구 `검침을 완료한 날에는 알림을 보내지 않아요.`.

### 4.2 계량기 교체 이력 화면

- 최신순 목록.
- 각 행에 교체일, 이전 검침값, 새 기준값, 사진 인식 또는 직접 입력 표시.
- 이력 없음, 로딩, 오류, 재시도 상태.

### 4.3 앱 초기화 카드

`처음부터 보기`와 완전 초기화를 구분한다.

- `처음부터 보기`는 기존처럼 코인·아이템·검침 기록을 유지하고 온보딩만 다시 보여준다.
- `앱 초기화`는 서버와 로컬의 모든 현재 기기 데이터를 삭제한다.
- 위험 동작은 붉은 계열 버튼과 두 단계 확인을 사용한다.

## 5. 알림 탭 이동

알림의 `extra`에 다음 값을 넣는다.

```json
{ "route": "camera" }
```

앱 시작 시와 실행 중 `localNotificationActionPerformed` 이벤트를 받아 루트 화면을 검침 촬영 흐름으로 전환한다. 알 수 없는 route는 무시하고 기본 홈 화면을 유지한다.

## 6. 오류 처리

- 알림 권한 거절은 앱 오류로 취급하지 않고 알림만 꺼진 상태로 유지한다.
- 알림 예약 변경 실패 시 이전 로컬 설정값과 기존 예약을 유지한다.
- 교체 이력 조회 실패는 해당 화면 안에서만 오류와 재시도를 표시한다.
- 초기화 서버 실패 시 어떤 로컬 데이터도 삭제하지 않는다.

## 7. 테스트 전략

### 7.1 백엔드

- 기준점 행을 교체 이력 응답으로 매핑한다.
- 교체 이력이 최신순이며 기기별로 분리된다.
- 초기화가 현재 기기의 Reading과 Settings만 삭제한다.
- 다른 기기 데이터는 유지된다.
- 반복 초기화가 안전하다.

### 7.2 프론트

- 알림 기본값은 꺼짐과 오후 8시다.
- 켜기, 끄기, 시간 변경이 어댑터 계약을 지킨다.
- 권한 거절 시 설정과 UI가 꺼짐을 유지한다.
- 검침 저장 성공만 완료일을 갱신하고 다음 날부터 재예약한다.
- 알림 탭 route가 촬영 화면을 연다.
- 교체 이력 로딩·빈 상태·오류·정상 목록을 표시한다.
- 글자 크기 세 단계가 `0.9·1.0·1.15`를 적용한다.
- 초기화 서버 실패 시 로컬 상태가 유지된다.
- 초기화 성공 시 알림, 앱 상태, 기기 ID가 삭제된다.

### 7.3 Android 실기기

- 알림 권한 허용과 거절.
- 설정 시각 부근 알림 수신.
- 알림 탭 후 촬영 화면 이동.
- 당일 검침 완료 후 그날 알림 미표시.
- 시간 변경과 알림 해제.

## 8. 완료 조건

- 계정 없이 모든 기능이 현재 기기 ID로 분리된다.
- 웹에서 설정 UI, 교체 이력, 초기화 계약이 검증된다.
- Android에서 로컬 알림 권한·예약·탭 이동·당일 건너뛰기가 실측된다.
- 앱 초기화는 서버 성공 전 로컬 데이터를 삭제하지 않는다.
- 기존 지역 설정, 검침, 이력, 리포트, 상점 기능이 회귀하지 않는다.
