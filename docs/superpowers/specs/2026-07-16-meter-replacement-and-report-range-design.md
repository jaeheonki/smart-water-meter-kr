# 계량기 교체 기준점과 리포트 기간 표시 설계

## 목적

계량기 교체·초기화로 누적 검침값이 낮아지는 정상 상황을 지원하면서 음수 사용량과 잘못된 요금 계산을 막는다. 에너지 리포트에는 집계 대상인 이번 기간과 비교 대상인 이전 기간을 명시한다. 두 변경은 Capacitor Android 래핑 전에 웹과 API에서 검증한다.

## 결정 사항

- 감소값과 동일값은 기본적으로 계속 422로 거절한다.
- 사용자가 계량기 교체를 명시적으로 확인한 경우에만 해당 값을 새 기준값으로 저장한다.
- 교체 전 이력은 삭제하지 않는다.
- 교체 직전 검침과 새 기준값 사이에는 사용량·요금 구간을 만들지 않는다.
- 새 기준값 다음 검침부터 사용량·요금을 다시 계산한다.
- 주간·월간·연간은 오늘을 포함한 최근 7일·30일·365일이라는 현재 규칙을 유지한다.
- 리포트에는 이번 기간과 이전 기간의 시작일·종료일을 모두 표시한다.
- 새 라이브러리, TypeScript, 상태관리 도구, CSS 프레임워크는 추가하지 않는다.

## 데이터 모델과 기존 DB 호환

`Reading`에 `is_baseline: bool = False`를 추가한다. 일반 검침은 `False`, 사용자가 확인한 계량기 교체 기준값은 `True`다.

SQLModel의 `create_all()`은 기존 SQLite 테이블에 열을 추가하지 않으므로 서버 시작 시 `PRAGMA table_info(reading)`로 열 존재 여부를 확인한다. 열이 없을 때만 다음과 동일한 SQLite 변경을 수행한다.

```sql
ALTER TABLE reading ADD COLUMN is_baseline BOOLEAN NOT NULL DEFAULT 0
```

기존 행은 모두 일반 검침으로 유지된다. 마이그레이션은 반복 실행해도 추가 변경이 없는 방식으로 테스트한다.

## API 동작

`POST /meter/manual` 요청에 `reset_baseline: bool = false`를 추가한다.

- 일반 요청은 현재처럼 최신값 이하를 422로 거절한다.
- `reset_baseline=true` 요청은 최신값과 비교해 사용량을 계산하지 않고 새 기준값으로 저장한다.
- 응답에는 `baseline_reset: bool = false`를 추가한다.
- 기준값 저장 응답은 `first_reading=false`, `baseline_reset=true`이며 사용량·요금·환경 필드는 비어 있다.
- 최초 검침은 기존처럼 `first_reading=true`, `baseline_reset=false`다.
- 최신값 조회부터 기준점 저장까지 기존 `BEGIN IMMEDIATE` 트랜잭션 안에서 실행한다.

이 구분으로 최초 검침 완료 UI와 계량기 교체 완료 UI를 혼동하지 않는다.

## 이력 계산

이력 라우터는 `Reading`을 시간순으로 순회한다. 인접한 두 행 중 뒤쪽 행의 `is_baseline`이 `True`면 그 구간만 건너뛴다. 기준값과 그 다음 일반 검침의 구간은 정상 계산한다.

예시는 다음과 같다.

```text
1000 → 1100 → [교체 기준 20] → 35
계산 구간은 1000→1100, 20→35다.
1100→20 구간은 이력과 리포트에 생성하지 않는다.
```

## 프론트엔드 흐름

일반 저장이 422를 반환하면 현재 안내와 함께 `계량기를 교체했어요` 버튼을 제공한다. 버튼을 누르면 기존 기록 보존과 해당 구간 미계산을 설명하는 확인 UI를 한 번 더 표시한다.

사용자가 최종 확인하면 동일한 검침값을 `reset_baseline=true`로 다시 전송한다. 성공 시 `새 계량기 기준값을 저장했어요` 화면을 표시한다. 취소하면 입력 화면으로 돌아가며 DB에는 아무것도 저장하지 않는다.

네트워크 오류와 일반 저장 오류는 기존 안내를 유지한다.

## 리포트 기간 표시

`getPeriodDateRange()` 결과를 리포트 화면에서도 사용한다.

- 기간 탭 바로 아래에 `이번 기간 2026.07.10 ~ 2026.07.16` 형식으로 표시한다.
- 비교 카드의 두 행은 각각 이번 기간과 이전 기간 날짜를 표시한다.
- 날짜 지정은 선택한 `from`·`to`와 `getPreviousDateRange()` 결과를 같은 형식으로 표시한다.
- 로딩, 오류, 빈 이력 상태에서도 선택한 기간은 계속 보인다.
- 집계 규칙과 API 호출 방식은 변경하지 않는다.

## 테스트와 완료 기준

- DB 마이그레이션 최초 실행과 반복 실행을 테스트한다.
- 감소값 일반 요청은 422이며 행이 추가되지 않는지 테스트한다.
- 동일한 감소값을 기준점 요청으로 다시 보내면 저장되고 계산 필드가 비어 있는지 테스트한다.
- 기준점 직전 구간은 이력에서 빠지고 기준점 이후 구간은 계산되는지 테스트한다.
- 동시 검침 직렬화 회귀 테스트가 계속 통과해야 한다.
- 프론트 계약 테스트로 422 안내, 교체 확인, `reset_baseline` 재전송, 교체 완료 UI를 검증한다.
- 날짜 범위 순수 함수와 주간·월간·연간·날짜 지정 화면 표기를 검증한다.
- 전체 `pytest`, 전체 Node 테스트, Node 24 `npm run build`, `git diff --check`를 통과한다.
- 로컬 브라우저에서 일반 감소값 취소, 계량기 교체 확정, 이력 분리, 리포트 기간 표시를 확인한다.
- EC2 배포 후 동일 API 흐름과 health를 확인한다.

## 범위 밖

- 계량기 제조사·일련번호 관리.
- 여러 계량기를 동시에 관리하는 계정 기능.
- 과거 기준점 수정·삭제 UI.
- 기존 검침 데이터의 임의 삭제.
- Capacitor Android 프로젝트 생성과 실기기 E2E.
