# Android 실기기 런타임 복구 설계

## 배경

Android 실기기 검증에서 운영 API 중단과 앱의 오류 복구 부족이 함께 드러났다. 서버가 복구된 뒤에도 앱이 시작 시점의 `오늘 기록 없음` 상태를 유지해 신규 저장을 반복했고, 서버는 이미 존재하는 오늘 기록 때문에 409를 반환했다. 운영 DB에는 명시적 교체 기준점이 도입되기 전에 저장된 감소 구간도 있어 `/history`가 전체 500으로 실패했다.

별도로 갤러리 사진은 서버에 정상 전송되지만 인식 중 화면에 선택한 사진이 표시되지 않아 검은 화면을 분석하는 것처럼 보인다. 외부 Google Material Symbols 웹폰트는 Android WebView에서 로드되지 않을 때 아이콘 이름을 그대로 노출한다.

## 목표

- 촬영하거나 선택한 사진을 인식 중 화면에 표시한다.
- 사진 인식 요청이 12초 안에 끝나지 않으면 중단하고 같은 사진 재시도 또는 직접 입력을 제공한다.
- 모델이 정상적으로 인식 실패를 반환하면 기존처럼 직접 입력 화면으로 이동한다.
- 오늘 기록 상태가 오래되어 POST가 409를 반환하면 오늘 기록을 다시 확인하고 같은 값을 당일 수정으로 저장한다.
- 명시적 기준점 도입 전의 감소 구간 때문에 전체 이력과 리포트가 실패하지 않게 한다.
- Material Symbols를 APK 내부 자원으로 제공한다.
- 첫 검침과 빈 리포트가 계산 대기 상태임을 설명한다.

## 제외 범위

- 계정과 기기간 기록 동기화.
- 자동 네트워크 재시도와 백오프.
- 기존 운영 검침값의 삭제 또는 수치 변경.
- YOLOX 모델, 전처리와 검출 기준 변경.
- HTTPS 전환과 AWS 인프라 재설계.

## 설계

### 사진 인식 상태

`CameraFlow`는 현재 처리 중인 `File`과 해당 파일의 임시 object URL을 상태로 보관한다. 촬영·선택 직후 인식 프레임 안에 이 URL을 표시하고 스캔 라인을 겹친다. 화면 이탈이나 파일 교체 때 URL을 해제한다.

API 공통 요청 함수는 선택적 제한 시간을 받는다. `/meter/scan`만 12초 제한을 사용하며 다른 저장·조회 요청의 계약은 바꾸지 않는다. 제한 시간 또는 네트워크 오류가 나면 사진을 유지한 오류 상태로 전환해 `같은 사진 다시 시도`와 `직접 입력`을 제공한다. 사용자가 뒤로 가면 기존 카메라·갤러리 선택 화면으로 돌아간다.

### 당일 저장 복구

정상 경로는 기존처럼 앱이 가진 오늘 기록 유무에 따라 POST 또는 PUT을 사용한다. POST가 409를 반환하면 서버의 `/meter/today`를 다시 조회한다. 오늘 기록이 확인될 때만 동일한 입력을 PUT으로 한 번 저장한다. 409 이외의 오류와 오늘 기록 재조회 실패는 자동으로 덮어쓰지 않고 실제 오류 안내를 표시한다.

### 레거시 감소 구간

새 검침 저장의 감소값 거절과 명시적 `reset_baseline` 계약은 그대로 유지한다. 이력 계산은 과거 두 기록 사이에서 현재값이 이전값보다 작거나 같은 레거시 구간을 발견하면 그 한 구간만 계산에서 제외한다. GET 요청에서 DB를 수정하거나 자동으로 교체 이력으로 기록하지 않는다. 이후 정상 증가 구간은 계속 계산한다.

### 아이콘과 안내 문구

Material Symbols Rounded의 필요한 웹폰트 파일을 `frontend/public/fonts`에 포함하고 로컬 `@font-face`로 사용한다. 외부 Google Fonts 링크에서는 Material Symbols 요청을 제거한다.

첫 검침 완료 화면은 일일 목표를 계속 보여주되 이전 검침이 없어 달성률은 다음 검침부터 표시된다고 안내한다. 이력이 비어 있는 가계부와 리포트도 첫 검침 이후 다음 검침부터 사용량 구간이 만들어진다고 설명한다. 실제 API 실패 문구와 빈 상태 문구는 계속 구분한다.

## 오류 처리

- 사진 분석 12초 초과는 인식 실패가 아니라 서버 응답 지연으로 표시한다.
- 모델의 `success: false`는 기존 직접 입력 흐름을 유지한다.
- 저장 409는 서버에서 오늘 기록이 확인된 경우에만 PUT으로 복구한다.
- 레거시 감소 구간은 해당 구간만 제외하고 API 전체는 정상 응답한다.
- 그 밖의 저장 오류는 일반 실패로 숨기지 않고 상태에 맞는 안내를 제공한다.

## 검증

- API 제한 시간이 요청을 중단하는 단위 테스트를 RED에서 확인한다.
- 갤러리·촬영 파일의 미리보기와 동일 파일 재시도 계약을 RED에서 확인한다.
- POST 409 뒤 GET today와 PUT 순서를 검증한다.
- 감소 레거시 구간을 건너뛰고 이후 정상 구간을 반환하는 pytest를 추가한다.
- 로컬 아이콘 폰트와 외부 Material Symbols 제거를 검증한다.
- 첫 검침·빈 이력 안내 문구를 검증한다.
- 전체 pytest, Node 테스트, Vite 프로덕션 빌드, Capacitor sync와 Gradle Debug APK 빌드를 실행한다.
