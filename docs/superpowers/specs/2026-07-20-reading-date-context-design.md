# 가계부 서울 날짜와 이전 검침 안내 설계

## 목표

- UTC로 저장된 검침 시각을 한국 날짜로 변환해 가계부 구간 날짜를 정확히 표시한다.
- 직접 입력과 사진 인식 확인 화면에서 실제 직전 검침값과 날짜를 안내한다.
- 오늘 기록을 수정할 때는 오늘 값이 아니라 오늘 이전의 마지막 검침을 안내한다.

## 현재 문제와 원인

검침 시각은 SQLite에 UTC naive `datetime`으로 저장된다. 오늘 기록 판정은 이미 서울 날짜 경계를 UTC로 변환해 사용하지만, 이력 계산은 `recorded_at.strftime("%Y-%m-%d")`를 직접 호출한다. 따라서 한국 시간 자정부터 오전 9시 사이에 저장한 기록은 가계부에서 전날로 표시된다.

입력 화면은 오늘 기록만 전달받고 오늘 이전의 마지막 기록은 조회하지 않는다. 사진 인식 확인 화면의 `어제 검침 0234.412㎥` 문구도 실제 API 데이터가 아닌 고정값이다.

## 결정

### 날짜 변환

백엔드에 UTC naive 시각을 서울 날짜 문자열로 변환하는 작은 공용 함수를 둔다. `Reading.recorded_at`에 UTC 시간대를 부여한 뒤 `Asia/Seoul`에 해당하는 고정 UTC+9 시간대로 변환하고 `YYYY-MM-DD`를 반환한다.

`/history`의 각 구간은 시작·종료 기록 모두 이 함수를 사용한다. 프론트는 기존처럼 `YYYY-MM-DD` 라벨을 표시하므로 화면별 추가 시간대 계산은 하지 않는다.

### 이전 검침 조회

`GET /meter/previous`를 추가한다. 이 API는 한국 날짜 기준 오늘 시작 시각보다 앞선 기록 중 가장 최근 한 건을 반환한다.

응답은 다음 두 필드만 가진다.

- `reading_m3`는 직전 누적 검침값이다.
- `recorded_at`은 기존과 동일한 UTC 저장 시각이다.

기록이 없으면 JSON `null`을 반환한다. 오늘 기록이 이미 있어 수정하는 경우에도 오늘 행을 제외하므로 안내 값은 항상 오늘 이전의 마지막 검침이다.

### 프론트 데이터 흐름

앱 시작 시 오늘 기록, 이전 기록, 전체 이력을 함께 조회한다. 이전 기록은 `CameraFlow`에 별도 속성으로 전달한다.

직접 입력 화면과 사진 인식 확인 화면은 같은 안내 컴포넌트를 사용하지 않고, 현재 화면 구조를 유지한 채 동일한 표시 규칙만 적용한다.

- 기록이 있으면 `이전 검침 225.654㎥ · 7/19` 형식으로 표시한다.
- 기록이 없으면 `이전 검침 기록이 없습니다`라고 표시한다.
- 기존 사진 인식 화면의 고정 검침값은 제거한다.

직접 입력 다이얼의 초깃값 정책은 바꾸지 않는다. 오늘 기록 수정이면 오늘 값을 사용하고, 신규 등록이면 기존 시나리오 초깃값을 유지한다.

## 오류 처리

이전 검침 조회 실패가 촬영이나 직접 입력을 막아서는 안 된다. 앱 초기 조회에서 해당 요청만 실패하면 이전 기록을 `null`로 취급하고 입력 흐름은 계속 제공한다. 날짜 이력 조회 실패는 기존 가계부 오류 화면을 그대로 사용한다.

## 테스트

백엔드 테스트는 다음을 검증한다.

- UTC 2026-07-19 16:00 기록이 서울 날짜 2026-07-20으로 표시된다.
- `/meter/previous`가 오늘 행을 제외하고 직전 기록을 반환한다.
- 최초 검침 기기는 `/meter/previous`에서 `null`을 받는다.
- 기기별 데이터 분리가 유지된다.

프론트 테스트는 다음을 검증한다.

- 앱이 이전 검침 API를 호출하고 `CameraFlow`에 전달한다.
- 직접 입력과 사진 인식 확인 화면이 실제 이전 값과 서울 날짜를 표시한다.
- 이전 기록이 없을 때 빈 상태 문구가 표시된다.
- 고정된 `0234.412` 문구가 남아 있지 않다.

전체 Python·Node 테스트와 Vite 빌드를 실행한다. 프론트 변경이 포함되므로 Capacitor 동기화와 Android debug APK 빌드도 실행하고 `output/android/banguli-debug.apk`를 갱신한다.

## 범위 제외

- 과거 데이터의 `recorded_at` 값을 수정하지 않는다.
- 가계부의 구간 계산, 요금 계산, 색상 기준은 바꾸지 않는다.
- 하루 한 번 저장과 오늘 기록 수정 정책은 바꾸지 않는다.
- 검사 정확도와 카메라 흐름은 바꾸지 않는다.
